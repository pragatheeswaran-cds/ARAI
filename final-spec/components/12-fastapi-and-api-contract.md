# FastAPI and API contract

Version 1.8 (amended 2026-10-05) | Implementation baseline | Component API

## Requirements and boundary

Implement FastAPI under /api/v1 with bundled OpenAPI normative for schemas, methods, filters and errors. No old /jobs or /approve routes. Cover dataset list/register/detail, run list/submit/status, customer queue/case/reviews, style queue/detail and SKU drill-down, experiment list/report, health. Runs live under /runs; the v1.0 /inference-jobs paths are withdrawn.

Upload exactly seven named CSV parts plus manifest JSON string. Reject private/unknown fields, client paths and traversal; internal storage paths server-generated. Synchronous structural validation returns201 only accepted (existing identical dataset200); scoring async202. Invalid422, resource413, unknown404, not-ready/model/idempotency conflict409, unexpected500 safe code/request_id no stack/path/secret.

world_id/content immutable. Idempotency scope endpoint+dataset for inference; endpoint+world/customer for notes; key<=128 with canonical payload hash. Repeat same returns original resource; changed body409. Customer ID must belong to run world.

Stable cursor tied to run+normalized filters+sort; invalid/context-changed/misshapen422. TruthPage names the world it reveals (world_id). Customer order rank then unranked ID; styles by style_id. Default limit50,max100; empty items=[]/next_cursor=null. The customer queue comparison filter (all, model_only, baseline_only, both) partitions eligible customers by model versus return-rate-rule selection. Filters change display only, not run score/selection.

Run carries warnings recorded at scoring (fewer than 500 eligible customers, a category fallback, scores or inputs outside the training range, or scoring code changed since publication). Contract 1.3.0: every Metric carries code, ranking and slice, which identify it; name and scope are display text and may be reworded. Health carries queue_depth and worker_seconds_since_seen (null if no worker ever reported), which are informative and not part of scoring_ready. ExperimentSummary carries selected_candidate_id (the registered candidate) beside selected_model_id (the promoted bundle, null unless promoted). A nullable enumeration lists null among its values. Review fields reviewer_name/disposition/note/idempotency_key; dispositions needs_investigation,likely_legitimate,unresolved. Append-only, server timestamp, immutable origin run/model. Free-text attribution is not authenticated identity. Contract 1.4.0 (AM-55): Run carries review_budget, threshold_score, median_score, mean_return_rate with eligible_requested_units and eligible_purchased_units, and graph_edges, all null until the run succeeded; TimelineEvent carries the facts behind its sentence as nullable fields (order_id, order_line_no, quantity, size, reason_code, reason_group, day_in_window, window_days, line_status, item_received, linked_claim); Neighbor carries the neighbour's own risk_score, rank, selected_for_review and evidence_tags; the customer list takes a wardrobing filter; GET /runs/{run_id}/score-distribution returns twenty five-point score bins with the queue size at or above each lower edge. A filter chooses what is shown and the distribution counts stored rows; neither changes a score or a selection. Contract 1.5.0 (AM-56): Customer carries basket_expectation (actual, purchased and expected units, sd, band_low, band_high, z) and cleared_reason (size_bracketing, high_return_styles, as_basket_predicts, below_threshold, or null in the queue); Case adds expected_band_low, expected_band_high, bracketing_units, bracketing_kept_units and median_return_day as signals; Run carries heavy_returner_cutoff, the 90th percentile of the eligible raw return rates. Contract 1.6.0 (AM-57): Customer carries community {id, kind (ring, household), size} or null without a supported edge; Case carries community with method (components, louvain), size, selected_count, requested_units, purchased_units, coordinated_claim_matches, members[] (each member's own risk_score, rank, selected_for_review, eligibility_status, support units and evidence_tags) and edges[] {a, b, types, coordinated_claim_matches}; Run carries community_count and ring_count; the customer list takes community (all, ring, household, none) and community_id filters. Null for runs scored before 1.6.0. Contract 1.7.0 (AM-58): Customer carries tier (HIGH, MEDIUM, LOW; null without a score), gate_outcome (ESCALATE, HOLD, WARNING, LOW; a presentation rule, null without a score) and primary_signals (at most three of the evidence tags, ordered, each with label, family, value, denominator, unit); Case carries score_breakdown (method family_at_typical_values, typical_from, threshold_raw_score, families[] with raw_score_without, score_without, delta_points, in_queue_without, tier_without; null without a score or before 1.7.0) and rules_fired (five rules, fired nullable); the customer list takes tier and gate filters, which are the same rules in SQL. Contract 1.8.0 (AM-59): ReviewRequest and Review carry kind (note, open, request_approval, approve, reject, feedback; note is the default and every earlier row); request_approval, approve and reject need an earlier open (409 case_not_open) and approve or reject by the reviewer of the latest open is refused (409 second_reviewer_required, fixed message); Customer carries workflow {state (new, in_review, awaiting_approval, approved, rejected, auto_logged), opened_by, opened_at, decided_by, decided_at}, derived on read; the customer list takes state and exclude_reviewer filters. Contract 1.9.0 (AM-60): Style carries name, median_return_day, share_in_last_five_days, flagged_returner_share {numerator, denominator, share}, ring_returners, median_returner_score and reason_codes[] {code, group, lines, units}; StyleDetail carries returners[] (customer_id, risk_score, rank, selected_for_review, tier, community, requested_units, claim_lines, linked_claim_lines, return_lines, purchased_lines, last_reason_code) beside customer_ids. Contract 1.10.0 (AM-61): GET /experiments/{experiment_id}/curves?run_id=&max_points= returns Curves (synthetic_only, eligible_count, review_budget, heavy_returner_cutoff, abusers, legitimate_heavy_returners, points[] {k, model_abusers_caught, model_legitimate_heavy_reviewed, baseline_abusers_caught, baseline_legitimate_heavy_reviewed}) for a run on the experiment's truth world, 409 world_mismatch otherwise; ExperimentSummary carries git_sha (nullable) and train_seeds, validation_seeds, test_seeds, demo_seeds, stress_seeds. Contract 1.11.0 (AM-62): Case carries memo {status (ok, unavailable, pending, not_selected), summary, key_evidence[] {statement, panel, value, denominator}, alternative_explanations[], recommended_action, attempts, reason, model, generated_at}, content null unless ok; Run carries memos {selected, ok, unavailable, complete}, null until the run succeeded. Contract 1.12.0 (AM-63): Run carries stage_log[] {stage, at} and styles_with_verdict; POST /runs/{run_id}/cancel returns 202 with the run (interrupted, or running with the cancel requested), 409 run_finished for a finished run.

Contract 1.13.0 (AM-64): the review workflow is a closed state machine (case_already_open, case_not_open, case_decided, second_reviewer_required with names compared without case, out_of_scope; a decision needs a reading, 422 request.decision_disposition); a NUL byte anywhere in a request is a 422; GET /runs/{id}/customers?cleared_heavy=true serves the cleared heavy returners (eligible, outside the review set, raw return rate at or above heavy_returner_cutoff); DELETE /datasets/{id} removes a dataset no run was scored on (409 dataset_in_use otherwise), while runs and notes keep having no delete; a missing static file is a 404, not index.html.

Contract 1.14.0 (AM-66, AM-67): Customer carries refunded_inr, claim_refunded_inr and absent_signals; Run carries refunds for the review set and the rule's set; GET /runs/{run_id}/customers/export answers the filtered queue as CSV with the list's filters (no cursor or limit), and the community kind text states the revised rule. All read from stored results; nothing is rescored.

Local explicit CORS UI origins; VM same-origin reverse proxy shared login covers both UI and API. No app signup/profile/password endpoints. Experiment truth reveal separated from inference and synthetic-labelled.

## Inputs, outputs and dependencies

- Inputs: Multipart CSV+manifest and typed JSON.
- Outputs: Responses matching contracts/openapi.yaml.
- Dependencies: Inference/storage.

## Acceptance criteria

| ID | Pass condition and required evidence |
|---|---|
| API-AC-01 | All actual requests/responses validate against OpenAPI including201/202 and documented errors. |
| API-AC-02 | Upload parts/limits/hash/count/ownership/path-traversal fixtures enforced. |
| API-AC-03 | Cursors return no duplicates/gaps and cannot cross run/filter. |
| API-AC-04 | Every UI action has an endpoint, with no training/refund/block/delete-note operation. |
| API-AC-05 | Unknown404, unfinished409, conflict409 and validation422 are distinguished. |
| API-AC-06 | Unlisted CORS origin denied; VM API unauthenticated denied. |
| API-AC-07 | comparison filter values partition eligible customers consistently with the run counts and stable cursors; ineligible customers appear only under all. |
| API-AC-08 | Every published metric has a code; Health reports the queue depth and the worker heartbeat; a login header that is not ASCII is refused with 401. |

Acceptance status is recorded per criterion in acceptance-register.csv (status, evidence, date, reviewer). Prose requirements are not implementation evidence.
